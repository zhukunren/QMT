# 东吴证券 · QMT 策略工坊

面向非技术投资者的蓝白色 Web 工作台。用户用自然语言描述投资想法，Codex 转换成策略规格；用户确认系统理解后，后端生成 QMT 内置 Python 脚本、执行静态规则检查并提供 GBK 文件下载。

这是可运行、可测试的商业项目初始版本，尚未完成券商客户端认证或生产上线验收。界面使用东吴证券官网公开标识与蓝白配色；正式 VI、文案、无障碍、合规及品牌使用授权仍需贵方验收。

## 本地启动

环境：Node.js 24+、npm、Python 3.9+。生成脚本面向 QMT 内置 Python 3.6；服务端校验器使用较新的 Python，不需要安装 QMT 或 pandas。

```powershell
npm ci
python -m pip install -r requirements.txt
Copy-Item .env.example .env
npm run dev
```

前端：<http://127.0.0.1:5174/>；后端：<http://127.0.0.1:8000/api/health>。二者独立启动：

```powershell
npm run dev -w @qmt/api
npm run dev -w @qmt/web
```

初次使用可从 **选择入门模板 / 从模板开始** 进入模板选择，比较买卖条件后点击 **使用模板创建 → 确认模板参数 → 确认并生成脚本 → 开始导入指引**。也可以将所选规则填入自然语言描述；模板创建不调用 AI。选择模板时股票、预算和生成用途沿用当前设置，同一模板保留已调整周期，切换模板则填入该模板的默认周期与阈值。

自然语言模式默认调用真正的 OpenAI `@openai/codex-sdk`。在运行后端的服务账号下完成 `codex login`，或在 `.env` 设置 `CODEX_API_KEY`。可选 `CODEX_MODEL` 指定账号可用的模型；未指定时沿用服务端 Codex 配置。不要把密钥写进前端，也不要在策略需求中填写交易账号或密码。SDK 自带原生 CLI；需要使用特定二进制时通过 `CODEX_PATH` 指定可执行文件绝对路径。

## 已实现

- 蓝白配色、东吴证券标识；自然语言为主入口，可选高级参数，响应式桌面与移动端导航。
- 手机导航支持焦点循环、Escape 关闭、背景滚动锁定与返回焦点；扩大触控目标并适配安全区。模板选择先预览买卖规则，参数表单按策略显示相关周期和阈值。空脚本库、筛选无结果、加载失败分别提供下一步操作。
- 新手导入指引从生成结果和列表下载后均可进入，按脚本分别记住“准备脚本、载入编辑器、设置历史回测、核对结果”步骤。源码复制复用下载接口的静态与完整性检查，完成标记仅记录浏览器内的操作进度，不更新客户端验收结果。实盘脚本进入独立的本地配置指引，并可复制为历史回测草稿。
- 桌面首屏显示创建主按钮，手机端固定底部操作；两种创建模式在当前页面会话中分别保留描述、参数和高级设置状态。生成结果和历史脚本使用独立工作区，提供固定操作栏、原始描述查看及基于已有策略修改入口。
- 示例策略一键填入；真实 Codex 需求理解；确认页逐项核对和修改标的、买卖条件、周期、阈值、运行方式与预算。修改会重新校验并保存为新的确认版本，原始记录保留，预算不可越过创建时设置的上限。
- 生成过程展示真实阶段、等待时间与处理记录；输入错误就近提示，失败后保留规则。查询中断可恢复原任务，已失败任务可重新生成，使用请求标识避免重复提交造成重复脚本。
- 双均线交叉、动量、均值回归三种受约束模板。自然语言不能忠实映射的需求拒绝生成，不静默删除不支持的条件。
- 只支持沪深主板普通 A 股、单标的、日线、QMT 内置 Python。提供独立实盘脚本模式；暂不支持 MiniQMT、止损止盈、网格、多股票等。
- Python 3.6 语法解析、生命周期、历史数据边界、依赖及危险调用、GBK 编码、重复 bar、资金与可卖持仓、交易参数等 9 类静态检查。
- 客户端验收单列为“待验收”；禁止将静态校验通过描述为已回测或保证正确。
- 新生成脚本使用中文注释、运行提示和自定义报错；买卖信号显示中文方向，异常提示说明检查方式，虚拟买卖请求与实际成交明确区分。导出真实 GBK `.py`；下载前复核规则与 SHA-256，校验或完整性不通过时阻止导出。历史已保存脚本保留原始内容及摘要，需重新生成才能采用新模板。QMT 或 Python 自身抛出的原始异常沿用客户端输出。
- 校验报告导出为 PDF，包含策略说明、参数、各项检查结果、客户端待验收事项、源码摘要和官方文档依据。内置并嵌入中文字体，无需客户端安装字体，历史脚本也可导出 PDF。
- SQLite 持久化策略规格、任务、脚本、报告和审计链；我的脚本支持名称/代码搜索、策略类型与校验状态组合筛选、重命名、复制为新策略和列表直接下载；最近记录展示股票代码与创建时间。
- 重命名保存为展示名称，同步用于列表、详情和下载文件名；原始代码及校验摘要保留。复制将已确认的参数带入模板草稿，调整并确认后生成新的脚本记录。
- 服务端限流、输入 schema、请求大小限制、可选 Bearer 令牌、CORS 白名单、安全响应头、超时、并发上限；非本地监听和生产模式强制令牌。

## 架构与正确性边界

```text
apps/web       React 19 + TypeScript + Vite，独立静态前端
apps/api       Fastify + TypeScript，REST API、Codex 编排、SQLite
packages/shared  前后端共用 Zod 规格与 DTO
apps/api/python  只解析 AST，不执行生成代码
tests          API 集成与可信模板的 Python 行为测试
```

生成链路：自然语言 → AI 提出文档查询 → 检索官方章节正文（可补查）→ Codex 输出规格与逐字引文 → Zod 与引用复核 → 通俗说明与用户确认 → 固定模板 → Python 静态校验 → 可追溯脚本。

模型不自由输出可执行 Python。模板只接收经过类型、范围与市场格式校验的字面量；风险预算只允许 AI 收紧，不能越过表单上限。Codex 使用独立临时工作目录、只读沙箱、关闭网络和搜索，并限制工具；检测到工具调用的结果会被拒绝。SDK 依赖宿主权限与沙箱，**上述配置不构成对恶意 agent 的进程级隔离保证**；生产务必使用独立低权限服务账号和容器/操作系统隔离，禁止复用研究员或交易员的个人 Codex 环境与插件。

生成脚本具有以下约定：

1. 信号与历史回测版本仅 `ContextInfo.do_back_test is True` 允许执行；`init` 与 `handlebar` 双重检查。实盘版本独立生成，要求标识明确为 False、本地启用开关及账户检查通过。未知环境均拒绝下单。
2. 按日线运行，数据截止前一根 K 线，`subscribe=False`，`dividend_type="none"`。信号有一根日线延迟；除权日可能形成伪信号，必须核对复权影响。
3. 仅在无持仓时买入，不加仓；预算取现金缓冲、总资产仓位预算和单笔预算最小值，向下取整到 100 股；卖出使用 QMT 报告的可用持仓。
4. 信号模式只打印信号；历史回测版本只允许对固定虚拟账户 `qmt_studio_backtest` 调用 `passorder`，`quickTrade=0`。QMT 回测参数中的资金、日期、手续费与滑点由用户设置。
5. 仓位限制是按前收盘价估算的**买入预算限制**，并非持续再平衡或市值比例硬保证；实际成交价、手续费、除权和涨跌停会影响结果。
6. 股票代码格式校验不确认上市状态、证券名称、ST 状态或停复牌。首版未接入交易日历、证券主数据或真实行情；没有收益数据或虚构回测结果。

静态检查包含固定模板规则和 AST 解析，不是一般 Python 安全分析器，也不能证明任意脚本的语义正确。实盘运行层还要求与应用维护的 Python 模板逐字一致；持久化文件 I/O 只在该固定运行层开放。生产链路只允许系统模板产物，浏览器没有上传或编辑任意可执行代码的接口。正式上线前应使用经过授权的真实历史行情、对照策略结果与东吴 QMT 精确版本完成回归和验收。

## 实盘脚本模式

在“生成用途”选择“实盘交易（QMT 本地启用）”，核对规则后生成独立实盘脚本。网页只生成和导出代码，不接受交易账号、密码，不连接交易柜台。三个策略均可选实盘；原有信号和历史回测模板保持回测环境限制。实盘静态通过后，东吴客户端验收仍为待办，不表示已经完成模拟柜台或真实交易联调。

实盘脚本默认 `LIVE_TRADING_ENABLED = False`。在 QMT 本地载入内置 Python 模型，在策略交易界面选普通股票账户（`ACCOUNT_ID` 留空使用该选择；也可在本地填写）。将 `ACCOUNT_READY_STATUS` 填为实际券商客户端登录正常时的精确 `m_strStatus` 文本；官方文档未统一枚举该字符串，因此不猜测任何值。未配置、登录状态不匹配、交易日期不符或查询异常均暂停新委托。模拟柜台验收后由用户在本地改为 `LIVE_TRADING_ENABLED = True`；该开关不是网页远程控制。

固定执行约定：

- 北京时间工作日 09:30–11:29、13:00–14:55 接受新委托。交易日列表、最新日线、上一交易日及历史行情末日必须对应；信号只用前一完整日线。真实 tick 必须为当日、15 秒内；异常时间、无对手价、涨跌停边界、ST/退市名称、异常价格均不发单。运行时取 QMT 行情、证券信息和交易日数据，无外部行情服务。
- 使用 `passorder` 的 1101 股数、11 指定限价、`quickTrade=1`。买入不加仓，保留 1% 现金缓冲；依据实际限价计算仓位和单笔预算，100 股取整。实盘买卖均受单笔金额上限约束，卖出只使用可卖数量，允许一次性卖出全部可卖零股。卖出可能需要多个交易日完成；买入仓位为预算限制，不能保证价格波动后的市值比例。
- 每个账户、股票每天最多一个交易意图。先将意图写盘并 fsync/原子替换，再调用异步交易接口；备注标识与柜台委托逐一匹配，累计成交量不按回调次数累加。委托号缺失、提交响应丢失、未知状态或错误数量均暂停，不盲目重发。账户掉线回报会拦截尚未更新的正向查询缓存。
- 每 3 秒查询订单。超过 60 秒未完成时请求撤单；请求发出不代表撤单成功，只有状态 53/54 且确认为本策略的撤单，才允许在当日有效时段重试剩余量一次。累计成交与重试限价预算仍受原始意图和单笔上限限制。部分成交不重复买入已成交部分；手动撤单、废单、未知提交均不自动补单。撤单接口明确返回 False 时最多再请求两次。
- 同一账户、股票仅允许一台电脑、一个实例。状态默认在用户目录 `.qmt_strategy_studio`，用账户和股票摘要命名，不在文件名保存明文账号。正常停止释放锁并保留 JSON；异常退出留下锁，必须先确认旧进程退出、核对委托，再手动移除相应 `.lock`，保留 `.json`。状态缺失而柜台存在同日生成器委托时停止恢复。损坏、异策略或不完整状态须人工恢复，不自动清空。不能通过切换电脑或目录绕过单实例约束。
- 停止模型不会保证柜台挂单已撤；未完成委托须在 QMT 委托界面继续管理。操作系统崩溃、磁盘故障、多个客户端或其他程序同时交易无法由单个本地脚本提供全局一致性保证。

撤单接口响应丢失、返回值不明确或失败时不授权自动补单；只有接口明确返回 True 且收到已撤终态才允许限次重试。已确认撤单但未执行的剩余量重试不会跨日延续；次日重新判断信号，未确认或结果未知的原始委托仍会阻断新单。

验收至少覆盖：正常买卖、限额与 T+1、部分成交、撤单待确认、撤单失败、重复/过时回报、无回报、提交响应丢失、断线、行情过期、非交易时段、正常重启、异常退出、损坏记录、跨日撤单和写盘失败。开发测试使用本地假柜台，未连接用户账户。真实东吴 QMT 版本、账户状态字符串及券商权限需在实际客户端核验。

实盘模板的官方引用会绑定账户/委托/持仓数据结构、`passorder`、`cancel`、回报函数、状态枚举、`get_full_tick`、`get_instrument_detail`、`get_trading_dates`、`is_last_bar`、定时任务及异步下单说明，随确认记录、脚本和 PDF 保存。文档页提供“实盘运行、下单与撤单、委托状态、委托回报、成交回报、账户和资金、实时行情”专题检索入口。

## API

- `GET /api/health`：公开最小可用性信息，不返回密钥。凭据“已检测到”不等于调用验证通过。
- `GET /api/sources`：全部官方文档目录、收录章节数与快照信息。
- `GET /api/documents/status`：正文库范围、页面/章节/片段数、采集时间和快照 SHA-256。
- `GET /api/documents/search?q=...&limit=6&pageId=...`：检索正文，最多返回 12 个片段，`pageId` 可选。
- `GET /api/documents/chunks/:id`：读取指定正文片段及同章节片段编号。
- `POST /api/plans`：`{ provider: "codex" | "template", prompt, spec }`；模板模式要求空 prompt。
- `POST /api/plans/:id/revisions`：`{ spec }`；重新校验编辑后的规则和原始预算上限，保存新确认版本并重新计算说明。
- `POST /api/jobs`：`{ planId, requestId? }`；只能引用后端持久化的策略规格，24 小时过期。同一请求标识重复提交会返回原任务；已失败任务重新生成需使用新的标识。
- `GET /api/jobs/:id`：任务状态、阶段与事件。
- `GET /api/artifacts`：最近 100 个脚本摘要；不返回全部源码。
- `GET /api/artifacts/:id`：脚本与校验详情。
- `DELETE /api/artifacts/:id`：删除该脚本及其校验报告，保留删除审计与原始生成历史；已下载文件和 QMT 中运行的策略不受影响。
- `POST /api/artifacts/:id/rename`：`{ name }`；保存 2–60 字的展示名称并记录审计，返回不含源码的脚本摘要。
- `GET /api/artifacts/:id/download`：复核后导出 GBK。
- `GET /api/artifacts/:id/report`：校对已保存源码完整性后，以 `application/pdf` 导出报告、策略规格和来源。

配置 `API_TOKEN` 后，除 health 外的接口要求 `Authorization: Bearer ...`。浏览器在“连接设置”填写该令牌，仅存内存。此令牌用于单工作台开发/受控内网访问，**不是多租户登录和授权系统**。

## 部署与上线前工作

`npm run build` 分别构建前端与后端；`npm start` 启动后端（当前使用 tsx 加载工作区源码）。前端产物在 `apps/web/dist/`，通过独立 Web 服务器托管，将 `/api/` 代理到后端。`deploy/nginx.conf` 提供反向代理示例。后端需要原生 Codex CLI、Node 24 和 Python，不能直接部署到不支持进程执行的纯静态或 Cloudflare Workers 环境。

生产建议在已批准的内网/私有云部署。设置 `.env` 的访问令牌、CORS、绝对数据目录，使用专属服务账号、HTTPS、单独的进程隔离和企业身份网关。当前 SQLite 为单实例本地存储；多实例需迁移数据库及任务队列。任务不跨进程自动恢复；服务重启会把未完成任务标为失败，允许用户重试。

仍需在正式商业上线前完成：东吴客户端版本和真实数据验证、策略语义独立复核、企业 SSO 与按用户数据隔离、角色权限和审核流程、访问和成本配额、外部模型数据使用审批、凭据管理、数据库加密与备份、数据留存与审计防篡改外存、可观测性与运维告警、负载和安全测试，以及正式品牌/合规验收。现有审计哈希链只便于本地完整性检查，不提供外部不可篡改保证。
